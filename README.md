# HAR & PAC Analyzer

A native macOS app for analyzing HAR exports alongside PAC files. Built for network and proxy troubleshooting — drop in a HAR capture and optionally a PAC file to immediately see what's required, what's missing, and what's likely breaking.

## Requirements

- macOS 14.0 or later
- Apple Silicon or Intel Mac (universal binary)

## Installation

Download the latest `HAR & PAC Analyzer.zip` from the [Releases](../../releases) page, unzip, and drag **HAR & PAC Analyzer.app** to your Applications folder.

The app is signed with a Developer ID and notarized by Apple — no Gatekeeper warnings.

## Features

### HAR + PAC Analysis
Load a HAR export from Chrome, Safari, or Firefox. Optionally load a PAC file to compare coverage. Drag and drop both file types directly onto the window.

### Overview Dashboard
A high-level snapshot across all requests: total requests, unique hosts, required domain count, optional domain count, and notable findings.

### Bypasses
Three columns showing likely-required domains, likely-optional domains (telemetry, analytics, ads), and a PAC-ready `dnsDomainIs` snippet for every registrable domain in the capture.

### Categories
All traffic grouped by service type — Core App, CDN / Static Assets, File Storage, Identity / Auth, API / Data, Telemetry, Analytics, Ads — each labeled with its access criticality.

### Resources
JavaScript and stylesheet URLs from the capture, useful for spotting blocked app bundles or missing CSS assets.

### Findings
Requests flagged for likely blocking or proxy issues: HTTP 0, 403, 407, 412, 451, 502–504, JavaScript or CSS URLs returning HTML (proxy block pages), slow DNS or TTFB, and Zscaler-specific signals.

### Statistics
Aggregate timing breakdown across all requests:
- Response time average, median, P95, min, max
- Distribution across `< 100 ms`, `100–500 ms`, `500 ms–1 s`, `> 1 s` buckets
- Per-phase averages: DNS, TCP Connect, SSL/TLS, TTFB (Wait), Download
- HTTP status code distribution by class (2xx / 3xx / 4xx / 5xx / 0) with counts and plain-English descriptions for every code seen
- Top 10 slowest requests

### PAC Export
Domains from the HAR not covered by the loaded PAC file, formatted and ready to paste directly into a PAC rule block:

```
    dnsDomainIs(host, ".example.com") ||
    dnsDomainIs(host, ".api.example.com") ||
```

When no PAC file is loaded, shows all registrable domains. When a PAC file is loaded, shows only the gaps — split into **Required Bypasses** (likely-required unmatched domains) and **All Unmatched Domains**. Each card has a one-click Copy button.

### PAC Rules
Browse and search all rules parsed from the loaded PAC file — `dnsDomainIs` and `shExpMatch` patterns listed alphabetically with copy-all buttons.

### Inspector Panel
Click any domain from any section to open a detail panel on the right showing:
- All matching hosts and requests for that domain
- Per-request HTTP status with description, method, elapsed time, MIME type, PAC match, and classification
- Full timing breakdown (DNS, Connect, SSL, TTFB, Receive)
- Request and response headers with important headers surfaced first

### Hosted PAC URL Bookmarks
Save named URLs to hosted PAC files in the sidebar. One click loads and parses the live PAC for comparison against the HAR — no manual file export needed.

## CLI Tool

A command-line analyzer is also included for scripted or terminal use:

```bash
swift run har-analyzer --har /path/to/export.har --pac /path/to/proxy.pac
```

## Building from Source

Requires Xcode 16 or later with Swift 6.

```bash
git clone https://github.com/miketrcs/har-pac-analyzer
cd har-pac-analyzer
./build.sh                   # debug build, launches the app
./build.sh --release         # release build (universal binary)
./build.sh --release --sign  # release build + code sign
```

## Traffic Classification

The classifier uses a two-tier approach:

1. **Tracker Radar database** — 5,400+ domains sourced from the [DuckDuckGo Tracker Radar](https://github.com/duckduckgo/tracker-radar) dataset, covering CDN, Analytics, Advertising, Social, Session Replay, Online Payment, and other categories. Subdomains not listed individually resolve to their parent domain.

2. **Heuristic fallback** — hostname pattern matching for domains not in the database (Canvas/Instructure, Okta, AWS, Azure, and similar ed-tech infrastructure). Required checks run before optional checks to minimize false-positive optional classifications.

The database is generated by `Scripts/generate_tracker_db.py` and compiled into the binary at build time. Re-run that script to pull a fresh snapshot from the tracker-radar repo.

PAC rule matching supports both `dnsDomainIs` and `shExpMatch` rules. `shExpMatch` glob patterns (`*`, `?`) are converted to anchored regular expressions for accurate coverage detection.

A domain is only flagged as needing a bypass if at least one of its observed hosts is absent from the PAC file — subdomains already covered by specific rules are not double-counted.
