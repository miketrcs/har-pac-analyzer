HAR & PAC Analyzer

Network & proxy troubleshooting for IT teams

Drop in a HAR capture from any browser and optionally a PAC file to instantly see which domains need bypass rules, which are optional telemetry or ads, where the PAC has gaps, and what the most likely proxy breakage signals are.

Quick Start

  1. Export a HAR file from your browser (Chrome: DevTools → Network tab → right-click → Save all as HAR with content; Firefox/Safari: similar).
  2. Drag the .har file onto the app window, or use File → Open HAR… (⌘O).
  3. Optionally load a PAC file via File → Open PAC File… (⌘⇧O) or select a saved hosted PAC URL from the sidebar.
  4. Review the Overview dashboard. Click any domain to open the Inspector Panel for a full per-request breakdown.
  5. Go to PAC Export to copy ready-to-paste dnsDomainIs rules for the domains you want to add to your PAC file.

Loading Files

HAR Files

HAR (HTTP Archive) is a JSON format that browsers use to export network activity. Any .har or .json file in HAR 1.2 format is supported.

  • Chrome/Edge: DevTools → Network tab → right-click any request → Save all as HAR with content
  • Firefox: DevTools → Network tab → gear icon → Save All As HAR
  • Safari: Web Inspector → Network tab → Export button
Tip: Capture a full page load — from a fresh tab — to get the most complete picture of what domains a site requires.

PAC Files

Load a .pac, .js, or .txt file via File → Open PAC File… or by dragging it onto the window. When a PAC file is loaded:

  • A PAC Coverage metric appears in the hero row
  • The Bypasses and PAC Export sections show only domains not already covered by the PAC
  • The PAC Rules section shows all parsed rules from the file
  • The Inspector Panel shows a PAC match or "no match" for each request

Use Clear in the sidebar to remove the PAC and return to showing all domains.

Hosted PAC URLs

If your PAC file is served from a URL (e.g., a Zscaler or on-premise PAC server), save it in the sidebar with Add Hosted PAC URL. Give it a friendly name and paste the URL. From then on, one click of Load fetches the live PAC file and re-runs the analysis — no manual export needed.

Saved URLs are stored locally in the app's preferences and are never shared or synced. The PAC URL itself is not committed to any repository.

Overview

Shows three summary cards side-by-side:

  • App Traffic — the top required-bypass domains, i.e., the most likely things that need to be in your PAC file
  • PAC Coverage — domains from the HAR that are missing from the loaded PAC (empty if no PAC is loaded)
  • Signals — high-level proxy warnings surfaced from the capture

Below the cards, the top traffic categories are shown. Switch to Categories for the full list.

Bypasses

Three columns driven by the traffic classifier:

  • Likely Required — domains classified as Likely Required. These are the strongest candidates for PAC bypass rules.
  • Likely Optional — domains classified as Likely Optional (telemetry, analytics, ads, session replay). Review these carefully — most can be left out of the PAC file.
  • PAC Snippet — all registrable domains from the HAR in dnsDomainIs format. When a PAC file is loaded, this shows only unmatched domains.

Click any domain in these lists to open the Inspector Panel for that domain.

Categories

All traffic grouped by service type. Each group shows the classifier's category, its criticality label, and the list of hostnames. Use the search bar to filter across categories and hostnames.

Categories: Core App, CDN / Static Assets, File Storage / Media, Identity / Auth, API / Data, Telemetry / Monitoring, Analytics / Tracking, Ads / Marketing, Third-Party Support, Unknown.

Click any hostname chip to jump to its Inspector detail.

Resources

JavaScript and stylesheet URLs from the capture, grouped into two cards. Useful for spotting blocked app bundles (JS returning HTML instead of script content) or missing CSS assets (layout looks incomplete).

These URLs come directly from the HAR and are not filtered through the classifier — they represent every script and stylesheet the page attempted to load.

Findings

Requests that are likely blocked, intercepted, or experiencing proxy-related trouble. The analyzer flags:

  • HTTP 0 — no response received; likely blocked by a firewall, proxy, or network failure
  • HTTP 403, 407, 412, 451 — policy blocks, proxy auth challenges, legal blocks
  • HTTP 502, 503, 504 — gateway or upstream failures
  • JS/CSS returning HTML — a proxy block page is being served instead of the real file
  • Slow DNS or TTFB — timing signals that suggest proxy overhead or routing issues
  • Zscaler / proxy signals — Proxy-Authenticate headers, policy challenge responses
  • Non-standard ports — traffic on ports other than 80/443 that proxy policies may not intercept

Statistics

Aggregate performance data across all requests in the capture:

  • Response Time — average, median, P95, min, max, and a distribution chart across four buckets
  • Timing Phases — per-phase averages for DNS lookup, TCP connect, SSL/TLS handshake, TTFB (Wait), and download, normalized against the slowest phase
  • Status Groups — 2xx / 3xx / 4xx / 5xx / 0 with counts and percentages
  • Status Code Detail — every HTTP status code seen, with a plain-English explanation
  • Alternate Ports — ports other than 80/443 with request counts and hostnames
  • Slowest Requests — top 10 requests by total elapsed time
Tip: HAR fields that report -1 are excluded from phase averages. This is normal — browsers only populate some timing fields.

PAC Export

Ready-to-paste PAC rules for domains in the HAR. Two cards appear depending on whether a PAC file is loaded:

  • Required Bypasses — only the likely-required domains that are missing from the PAC (or all required domains if no PAC is loaded)
  • All Unmatched Domains — every domain from the HAR not covered by the PAC (or every domain if no PAC is loaded)

Each card has a Copy button that copies the full snippet to your clipboard. The format is:

    dnsDomainIs(host, ".example.com") ||
    dnsDomainIs(host, ".api.example.com") ||

Paste these lines into the condition block in your PAC file's FindProxyForURL function.

PAC Rules

All rules extracted from the loaded PAC file, sorted alphabetically and split by type:

  • dnsDomainIs — exact domain-suffix matches, e.g. dnsDomainIs(host, ".example.com")
  • shExpMatch — glob-pattern matches, e.g. shExpMatch(host, "*.example.com")
  • Other / Raw — any other recognized expressions

Use the filter field to search rules by pattern. The count updates live. Each card has a Copy All button.

If no PAC file is loaded, this section shows a prompt to load one.

Inspector Panel

The right-hand panel updates whenever you click a domain in any section. It shows everything the analyzer knows about that domain:

  • Metric row — unique hosts under this registrable domain, total request count, and finding count
  • Classification — the service category and criticality assigned by the classifier
  • Hosts — the distinct hostnames seen under this domain (e.g., cdn.example.com, api.example.com)
  • Requests — all requests for this domain, sorted by severity then by elapsed time. Click a request to load it in the detail pane below.
  • Request Detail — full breakdown for the selected request: URL, method, HTTP status with description, elapsed time, port, MIME type, PAC match, classification with reason, and any detected issues
  • Timing Breakdown — a grid showing each HAR timing phase (DNS, Connect, SSL, Send, Wait/TTFB, Receive) in milliseconds
  • Request & Response Headers — important headers surfaced first (Host, Accept, Content-Type, Authorization, etc.); all other headers accessible via disclosure group
Tip: You can also click a URL in the Findings section to jump straight to the Inspector for that domain.

Traffic Classification

Every hostname in the HAR is classified using a two-tier approach:

Tier 1 — Tracker Radar database

5,400+ domains from the DuckDuckGo Tracker Radar dataset. This covers CDN, Analytics, Advertising, Social, Session Replay, Online Payment, and other categories at scale. Subdomains not listed individually are resolved to their parent registrable domain.

Tier 2 — Heuristic fallback

Pattern matching for domains the database doesn't know about — including Canvas/Instructure-specific hosts, Okta, AWS services, Azure blobs, and general app/auth hostname patterns. Required-traffic checks run before optional checks to minimize false-positive optional classifications.

Criticality labels

  • Likely Required — the classifier believes this domain needs to be bypassed for the site to load. Core app hosts, CDNs, auth endpoints, file storage.
  • Likely Optional — telemetry, analytics, ads, session replay. The site almost certainly functions without these. Review before adding to PAC.
  • Needs Review — the classifier couldn't determine criticality. Inspect manually.
Important: Classifications are best guesses based on hostname patterns and a third-party database. Always verify before adding or removing PAC rules — especially for domains you don't recognize.

PAC Rule Matching

The analyzer parses two kinds of rules from PAC files:

dnsDomainIs

dnsDomainIs(host, ".example.com")

Matches any hostname that ends with .example.com. The leading dot means subdomains match: cdn.example.com, api.example.com, etc. The registrable domain itself (example.com without a subdomain) does not match unless the rule is dnsDomainIs(host, "example.com").

shExpMatch

shExpMatch(host, "*.example.com")
shExpMatch(url, "*/api/*")

Shell-style glob patterns. * matches any sequence of characters, ? matches a single character. The analyzer converts these to anchored regular expressions for accurate coverage detection against observed hostnames and URLs.

A domain is only flagged as unmatched if at least one of its observed specific hosts is absent from the PAC rules. Subdomains already covered by a broader rule are not double-counted as gaps.

CLI Tool

A command-line version of the analyzer is included for scripted or terminal use:

har-analyzer --har /path/to/export.har
har-analyzer --har /path/to/export.har --pac /path/to/proxy.pac

Output is colorized ANSI text covering required domains, optional domains, findings, PAC coverage, and Zscaler signals. Pipe to a file or a pager as needed.

To build and run from source:

swift run har-analyzer --har export.har --pac proxy.pac

Exporting Reports

Use File → Export Report… (⌘S) to save a Markdown report of the current analysis. The report includes:

  • Summary table (total requests, unique hosts, required count, optional count, findings, PAC coverage)
  • Required bypass domains and the full PAC snippet
  • PAC gaps (unmatched domains, if a PAC file was loaded)
  • All findings with HTTP status, category, PAC match, and issue descriptions
  • Optional domains list

The Markdown file is suitable for pasting into a ticket, email, or documentation system.

For individual domain lists or PAC snippets, use the Copy buttons throughout the dashboard, or the Quick Actions in the sidebar:

  • Copy PAC Snippet — all required-bypass domains in dnsDomainIs format
  • Copy Required Domains — plain domain list
  • Copy Optional Domains — plain domain list
